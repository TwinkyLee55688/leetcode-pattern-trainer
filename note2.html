Best interview sentence: In Weighted Union-Find, weight[x] represents the ratio between x and its parent. During path compression, I update weight[x] so it directly represents x / root. For a query A / B, if they share the same root, the answer is weight[A] / weight[B].

10. Weighted Union-Find Performance

My original sentence

How about its performances?

Grammar correction / simple version

What is the time and space complexity of the Weighted Union-Find solution?

Best interview sentence: Compared with BFS, Weighted Union-Find is better when there are many queries. BFS may traverse the graph for every query, while Union-Find can answer each query in almost constant time after preprocessing.

Complexity

  • V = number of variables
  • E = number of equations
  • Q = number of queries
  • Build time: O(E * alpha(V))
  • Query time: O(Q * alpha(V))
  • Total time: O((E + Q) * alpha(V))
  • Space: O(V)

alpha(V) is the inverse Ackermann function. It grows extremely slowly, so in practice it is almost constant.

Core Templates to Remember

DFS visited idea

Every time I find an unvisited node or land cell, I start DFS/BFS and mark the entire connected component as visited.

Union-Find cycle idea

If two nodes already have the same root, adding an edge between them creates a cycle.

Union-Find component count idea

Every node starts as its own component. Each successful union merges two components and reduces the component count by one.

Weighted graph idea

Each edge weight represents a ratio. The answer to a query is the product of weights along a valid path.

Weighted Union-Find idea

weight[x] = x / parent[x]. After path compression, weight[x] = x / root. Therefore, if A and B share the same root, A / B = weight[A] / weight[B].
