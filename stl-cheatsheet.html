Memory Rules
Vector has a back → push_back / pop_back Stack / Queue / Heap → push / pop Stack & Heap expose the top → top() Queue exposes the next in line → front() Set is a collection → insert / erase / count Map is key → value → mp[key] Pair has two fields → first / second
If I need a tail while building a linked structure, I should probably think about using a dummy node too.
Interview Gotchas
1. pop() removes — it does NOT return. 
// queue
int x = q.front();
q.pop();

// stack
int x = st.top();
st.pop();

// priority_queue
int x = pq.top();
pq.pop();
2. mp[key] may create a missing key.

If you only want to check existence: 

if (mp.count(key)) {
    ...
}

// or
if (mp.find(key) != mp.end()) {
    ...
}
3. Structured binding makes pair/map code cleaner. 
pair<int, int> p = {3, 5};

auto [a, b] = p;


for (auto& [key, value] : mp) {
    ...
}

10-Second Recall
// vector
v.push_back(x);
v.back();
v.pop_back();


// stack
st.push(x);
st.top();
st.pop();


// queue
q.push(x);
q.front();
q.pop();


// priority queue
pq.push(x);
pq.top();
pq.pop();


// set
s.insert(x);
s.count(x);
s.erase(x);


// unordered_map
mp[key] = value;
mp.count(key);
mp.erase(key);


// pair
p.first;
p.second;
Which One Should Pop Into My Mind?
BFS → queue DFS iterative → stack Top K → priority_queue Existence / visited → unordered_set Key → value lookup → unordered_map Dynamic array → vector Two values traveling together → pair Both ends matter → deque
